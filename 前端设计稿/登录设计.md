# 登录设计

## 1. 目标
为 408 备考 App 定义一套可直接进入 UI 设计与 Flutter 实现的移动端登录方案，服务主链路：

`启动页 → 登录/注册 → Onboarding → 目标创建成功 → 全局计划生成 → 今日计划`

这不是独立账号页，而是整个产品主闭环的入口页。登录的任务只有三个：
1. 让用户快速进入系统
2. 明确登录后会继续做什么
3. 稳定把用户送进 Onboarding，而不是停在账号体系里

---

## 2. 设计依据

### 2.1 来自现有文档的确定信息
- 当前产品状态机已经明确为：`未登录 → 已登录 → Onboarding → 全局计划就绪 → 本周激活 → 今日 check-in → 今日执行 → 晚间复盘 → 周复盘`
- 主跳转链路已经明确：`启动页 → 登录页 → Onboarding`
- Onboarding 结构原则已经明确：`顶部轻导航 + 右上 Skip + 中部卡片化选择 + 底部固定主 CTA`
- 后端认证主链已具备：本地注册、登录、当前账户查询、注销
- 登录/注册属于开放口，登录后才进入受保护主链路
- 产品整体气质应是：温暖、克制、陪伴感、学习导向，不做强销售感或强工具压迫感

### 2.2 来自 Refero 参考的共性结论
结合登录页、欢迎页、onboarding/account setup 页参考，抽出以下稳定模式：
- 登录页首屏应只保留一个核心动作，避免同时出现过多分支
- “先输入邮箱/手机号，再判断登录或注册”是低阻力方案，尤其适合新用户混合入口
- Onboarding 更适合使用卡片化选择和底部固定 CTA，而不是长表单一次填完
- 异常提示优先顶部 banner 或字段就近提示，不要只在提交后弹全屏错误
- 教育/陪伴型产品更适合浅暖底色、留白、轻插画、小剂量情绪文案

---

## 3. 页面角色定义

### 3.1 启动页的职责
启动页不是介绍功能的大海报，而是一个很短的缓冲页，只负责：
- 建立品牌识别
- 判断登录态
- 决定去登录页还是直接恢复主流程

### 3.2 登录页的职责
登录页只负责完成账号进入，不承担完整画像采集。

应明确告诉用户：
- 登录后将继续初始化你的备考方案
- 账号只是进入方式，真正价值在后面的计划与执行系统

### 3.3 Onboarding 的职责
Onboarding 负责补齐排程所需的第一批关键输入：
- 考试时间
- 当前基础
- 每日可用时长
- 学习偏好
- 风险倾向或拖延特征

因此登录页要轻，Onboarding 要结构化。

---

## 4. 信息架构

推荐拆成 4 个连续界面，而不是把登录、注册、找回密码、画像全部塞进一屏。

### 4.1 S0 启动页
**目标**：3 秒内完成品牌确认与路由判断

**页面结构**：
- 顶部留白 / 品牌 logo
- 中部主视觉：暖杏橙 + 奶白系轻插画，可表现“计划、书本、陪伴、成长”
- 主标题：`让你的 408 计划真正跑下去`
- 副标题：`不是只排一次计划，而是每天陪你学下去`
- 底部主按钮：`开始登录`
- 次按钮：`我已有账号`
- 最底部轻文案：`登录后继续完成你的备考初始化`

**路由规则**：
- 已登录且 onboarding 未完成 → 直接回到上次 Onboarding 步骤
- 已登录且计划已生成 → 直接进今日页
- 未登录 → 进入登录页

---

### 4.2 S1 登录/注册合流页
**推荐方案**：单入口合流，不先硬分“登录”还是“注册”

先收集一个主身份字段：
- 优先推荐：手机号
- 备选：邮箱

#### 页面结构
- 顶部：返回
- 标题：`先登录，继续你的备考计划`
- 副标题：`我们会检查你是否已有账号，没有就直接帮你创建`
- 主输入框：`手机号或邮箱`
- 主按钮：`继续`
- 次级入口：`使用密码登录`
- 底部协议文案：`继续即表示你同意《用户协议》《隐私政策》`

#### 这样设计的原因
- 新用户不需要先理解“注册”和“登录”的差别
- 老用户也不会因为选错入口而中断
- 适合当前 MVP 阶段，把路径做短

#### 交互规则
- 输入合法前，`继续` 按钮禁用
- 点击继续后：
  - 若账号存在 → 进入验证码登录或密码登录
  - 若账号不存在 → 进入验证码验证并自动创建账号

---

### 4.3 S2 验证页
根据账户情况分两条轻分支，但保持同一视觉骨架。

#### 方案 A：验证码验证
适合默认主链路。

**页面结构**：
- 标题：`输入验证码`
- 说明：`验证码已发送至 138****1234`
- 6 位验证码输入区
- 主按钮：`登录并继续`
- 文本按钮：`59s 后重新发送`
- 次级按钮：`改用密码登录`

**适用场景**：
- 新用户自动注册
- 老用户无密码或更偏好快捷登录

#### 方案 B：密码登录
适合已有账号用户。

**页面结构**：
- 标题：`输入密码`
- 已识别账号摘要：`138****1234`
- 密码输入框
- 辅助入口：`忘记密码？`
- 主按钮：`登录`
- 次级入口：`改用验证码登录`

**注意**：
密码页不要和手机号/邮箱输入页挤在同一屏，减少认知负担。

---

### 4.4 S3 登录后过渡页
登录成功后不要直接硬切到长问卷，建议加一个极短过渡页。

**目标**：把“账号进入”自然切换为“开始建立你的学习系统”

**页面结构**：
- 成功图形 / 勾选动画
- 标题：`登录成功`
- 副标题：`接下来用 1~2 分钟，帮你生成更适合你的备考方案`
- 主按钮：`开始初始化`

**跳转**：
- 主按钮 → Onboarding Step 1
- 若有恢复上下文 → 文案可替换为 `继续上次填写`

---

## 5. 登录页详细结构方案

这里指核心的 `S1 登录/注册合流页`。

### 5.1 页面层级
从上到下：
1. 顶部导航
2. 品牌识别与价值文案
3. 账号输入区
4. 主 CTA
5. 备用登录方式
6. 协议与安全说明

### 5.2 顶部区域
- 左上：返回
- 右上：可不放动作，保持安静
- 如从启动页进入，不再重复放 logo 大标题，可只保留小 logo

### 5.3 价值区
建议高度不要过大，避免把输入框压到首屏以下。

**推荐文案**：
- 标题：`先登录，继续你的 408 计划`
- 副标题：`登录后会进入备考初始化，系统会根据你的基础、时间和目标生成计划`

### 5.4 输入区
**主输入框 1 个**：
- label：`手机号或邮箱`
- placeholder：`请输入手机号或邮箱`
- 输入框高度建议 52
- 使用圆角描边，不用下划线样式

**输入法与键盘**：
- 手机号 → 数字键盘
- 邮箱 → email 键盘

### 5.5 CTA 区
- 主按钮：`继续`
- 宽度全宽
- 固定底部或紧跟输入区，二选一
- 如果页面整体较短，推荐固定在下半屏底部，增强确定性

### 5.6 次级入口
推荐只放 1~2 个：
- `使用密码登录`
- `我遇到问题了`

避免首屏同时出现：微信登录、Apple 登录、邮箱登录、短信登录、游客模式等过多选项。

### 5.7 底部说明
- `继续即表示你同意《用户协议》《隐私政策》`
- `你的计划、复习和学习记录会同步到账号`

第二句很重要，它解释了为什么要登录。

---

## 6. 登录与注册切换策略

### 6.1 不推荐的做法
- 顶部放两个同权 Tab：登录 / 注册
- 每个 Tab 都有一整套字段
- 让用户自己决定先选哪个

原因：
- 对首登用户不友好
- 易造成误判与切换成本
- 首屏信息密度过高

### 6.2 推荐的做法
用“识别账号状态”取代“先选登录还是注册”。

流程：
1. 用户输入手机号/邮箱
2. 系统检查是否存在账号
3. 已存在 → 登录路径
4. 不存在 → 注册并登录路径
5. 登录成功 → Onboarding

### 6.3 例外入口
如果业务上必须明确提供注册入口，可放在底部弱化文本：
- `没有账号？继续后会自动创建`

这样比单独大按钮更轻。

---

## 7. 登录后到 Onboarding 的衔接

### 7.1 原则
登录成功后，用户不应该面对一个“你已经完成了”的空白状态，而是立即进入下一步价值构建。

### 7.2 过渡文案建议
- `接下来我们会先了解你的基础和时间安排`
- `只需 1~2 分钟，就能开始生成你的备考方案`
- `后续也可以在“我的”里继续调整`

### 7.3 Onboarding 首段建议
登录后首段 onboarding 建议按下面顺序：
1. 考试信息与目标时间
2. 当前基础自评
3. 每日/每周可用时长
4. 学习偏好与重排偏好

### 7.4 页面结构原则
延续文档既定模式：
- 顶部轻导航
- 右上 Skip
- 中部卡片化选择
- 底部固定 CTA

但 Skip 不应出现在登录页，应该出现在 onboarding 中。

## 8. 状态设计

### 8.1 默认态
- 页面干净
- 继续按钮禁用
- 输入框未聚焦

### 8.2 输入中
- 输入框高亮
- 实时格式校验，但不过早报错
- 不在用户刚输入 1~2 位时就显示红字

### 8.3 校验失败
**字段级提示优先**：
- `请输入正确的手机号`
- `请输入正确的邮箱地址`

**顶部 banner 仅用于全局错误**：
- `当前网络异常，请稍后再试`
- `验证码发送失败，请稍后重试`

### 8.4 验证码发送中
- 按钮进入 loading
- 文案变成：`发送中...`
- 按钮禁用

### 8.5 登录提交中
- 主按钮 loading
- 页面其余关键入口禁用，避免重复提交
- 不建议全屏遮罩

### 8.6 登录失败
分三类：
1. 账号格式错误
2. 验证码/密码错误
3. 网络或服务异常

对应策略：
- 格式错误 → 字段下方报错
- 密码/验证码错误 → 字段下方 + 顶部轻提示
- 服务异常 → 顶部 banner + 重试按钮

### 8.7 恢复场景
如果用户曾完成部分 onboarding：
- 登录成功后提示：`已为你恢复上次的初始化进度`
- 主按钮：`继续填写`

---

## 9. 异常与边界场景

### 9.1 验证码收不到
给出明确次级入口：
- `重新发送`
- `改用密码登录`
- `联系客服`

### 9.2 账号已存在但用户以为自己是新用户
文案不要说“该账号已注册”，而用更柔和表达：
- `我们找到了你的账号，直接登录即可继续之前的进度`

### 9.3 密码错误多次
- 允许继续输入
- 明确给出 `忘记密码`
- 不要在移动端做过重惩罚式文案

### 9.4 网络异常
- Banner：`网络有点不稳定，请稍后重试`
- 按钮：`重试`
- 允许返回上一步

### 9.5 已登录但 token 失效
若用户从启动页恢复失败：
- 提示：`登录状态已失效，请重新登录`
- 直接进入登录页

## 10. 视觉规则

### 10.1 气质关键词
- 温暖
- 安静
- 有陪伴感
- 不压迫
- 有秩序感

### 10.2 色彩建议
沿用当前项目的暖色规则：
- 主色：`#E78A5B`
- 页面背景：`#FFF8F4`
- 卡片白底：`#FFFFFF`
- 主文本：`#2B211B`
- 次文本：`#7A685D`
- 边框：`#EEDFD6`
- 成功点缀：`#5FAF88`
- 错误：`#D96C6C`

### 10.3 登录页上的色彩职责
- 主色只用于主按钮、激活输入态、小面积强调
- 大背景保持奶白/浅暖色
- 不做整屏纯橙底
- 错误态不用主色，直接用 danger

### 10.4 插画建议
- 轻量，不做重运营海报
- 可出现书本、进度、时间块、陪伴型角色
- 风格偏柔和平面化，避免复杂 3D

### 10.5 版式建议
- 左右边距：16~20
- 输入框高度：48~52
- 主按钮高度：50~54
- 模块间距：16 / 20 / 24
- 标题不超过两行

## 13. 最终结论
这套登录设计的核心不是“把账号系统做全”，而是：

1. **登录入口极简**：先收一个身份字段，降低进入成本
2. **自动合流登录/注册**：减少用户分支选择
3. **登录后立即进入 Onboarding**：保证产品主价值连续
4. **全程异步友好**：明确 loading、错误、重试、恢复进度
5. **视觉保持温暖克制**：服务学习产品，而不是做互联网强转化页

如果后续继续细化，下一步最适合直接输出：
- 登录页低保真线框文稿
- Auth / Onboarding 页面树
- Flutter 组件拆分清单
