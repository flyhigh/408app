同时，当前项目的真实状态是：**后端和数据库骨架已经比较成熟，前端仍偏弱，真实 OCR / 对象存储 / 完整 AI 产物流还没有完全产品化**，所以前端设计必须优先保障 MVP 主链路跑通，并且从一开始就把**异步、失败、重试、占位、回退**设计进去。[5][11][29]

另外我已经结合 Refero 的 iOS 参考流和页面做了交叉调研，结论很明确：

- **任务/计划页** 最稳的是“卡片列表 + 进度 + 分组标签 + 单页只做一个核心动作”。  
- **AI 聊天页** 最稳的是“极简会话区 + 快捷问题 chips + 上下文来源卡片 + 长任务异步回传”。  
- **拍照/上传** 最稳的是“底部 action sheet 选择来源：拍照 / 相册 / 文件”。  
- **Paywall** 最稳的是“一个核心价值主张 + 2~3 个权益点 + 月/季/周期包切换 + 明确免费试用或会员差异”。

## 11. 今日计划详情页

### 11.1 这是什么界面
这是用户每天打开频率最高的页面，作用不是“展示很多信息”，而是让用户在 3 秒内知道：  
1. 我今天要做什么；  
2. 哪些是必须完成的；  
3. 如果今天时间变了，我该怎么重排。  
这个页面必须成为产品的真正首页，因为产品核心价值不是“生成计划”，而是**把计划执行下去，并在突发情况下继续托住复习节奏**。[7][9]

### 11.2 页面结构
**顶部区域**
- 页面标题：`今日计划`
- 日期显示：`4月3日 周三`
- 顶部右侧图标：
  - `铃铛`：通知中心
  - `···`：更多操作
- 顶部下方一行摘要：
  - `今日可用时长：3h 20m`
  - `已完成：2/7`
  - `复习任务：3`
  - `积压：4`

**核心卡片区**
1. **今日总进度卡**
   - 环形进度条
   - 文案：`今日完成 28%`
   - 子文案：`MUST 已完成 1/3，复习已完成 1/3`
   - 右侧小按钮：`查看周进度`

2. **MUST 任务分组**
   - 标题：`今天必须做`
   - 每个任务卡内容：
     - 任务标题，如 `OS - 进程同步基础`
     - 科目标识 / 学科色条
     - 预计时长
     - 任务来源：`今日计划` / `复习` / `补回任务`
     - 优先级标签：`MUST`
     - 状态：未开始 / 进行中 / 已完成 / 已阻塞
   - 右上角：`全部展开/收起`

3. **NICE 任务分组**
   - 标题：`有余力再做`
   - 默认折叠，只显示前 2 条
   - 用弱化视觉，不抢 MUST

4. **今日复习分组**
   - 按 D0 / D1 / D3 / D7 任务分层显示  
   - 这块一定要和学习任务并列，因为产品路线里复习闭环是明确的核心能力，而不是附属提醒功能。[6]

5. **今日风险提示条**
   - 如果任务总时长 > 今日可用时长：显示黄色提示条  
   - 文案如：`今日任务超载 45 分钟，建议立即重排`
   - 按钮：`去重排`

**底部固定操作区**
- 主按钮：`开始第一个任务`
- 次按钮：`突发重排`
- 文本按钮：`晚间复盘入口（晚上 18:00 后高亮）`

### 11.3 这个界面有哪些按钮，有哪些功能
#### 1）开始第一个任务
- 默认打开优先级最高且未开始的任务详情页
- 如果存在 overdue review，则优先弹出一个选择框：
  - `先做逾期复习`
  - `先做当前学习任务`

#### 2）任务卡点击
跳转到**任务执行页**，并携带：
- task_id
- goal_id
- subject_id
- knowledge_node_id
- 来源类型：新学 / 复习 / backlog

#### 3）任务卡右滑
- `完成`
- `延后`
- `标记受阻`
- `加入 backlog`

#### 4）任务卡右上角更多按钮
- `查看知识点`
- `问 AI`
- `改预计时长`
- `调整优先级`
- `移出今日`

#### 5）突发重排
直接进入**重排弹层/重排页**。  
这个入口必须非常显眼，因为 V0.2 就已经明确把**突发重排 + Backlog**作为主能力，而不是边缘功能。[6]

### 11.4 这个界面的关键交互
- 进入页面时，如果是当天第一次打开，顶部弹出 `今日简报卡片`：
  - `今天你有 3 小时 20 分钟`
  - `优先保住 3 个 MUST`
  - `建议先学 OS，再做 D1 复习`
- 支持下拉刷新：
  - 重新拉取今日 schedule version
- 如果后台返回新的 daily schedule version：
  - 顶部出现非阻断提示：`今日计划已更新`
  - 提供按钮：`查看变化`

### 11.5 状态设计
- **空状态**：今天还没有生成计划 → 按钮 `生成今日计划`
- **超载状态**：今日任务过多 → 黄色/橙色警示
- **中断状态**：有 1 个任务被标记受阻 → 顶部出现恢复提示
- **全完成状态**：展示庆祝插画，但底部仍保留 `去做复习` / `查看 Backlog`

### 11.6 跳转
- 今日计划页 → 任务执行页
- 今日计划页 → 重排页
- 今日计划页 → Backlog 页
- 今日计划页 → 晚间复盘页
- 今日计划页 → 知识点详情页
- 今日计划页 → AI 对话页

## 12. 任务执行页

### 12.1 这是什么界面
这是用户真正“开始学习”的页面。  
它不是笔记页，也不是纯计时器页，而是一个**任务执行工作台**。

### 12.2 页面结构
**顶部**
- 返回按钮
- 任务标题
- 右上角：`···`

**任务信息卡**
- 章节 / 知识点路径
- 任务目标
- 预计时长
- 当前已用时
- 本任务在全局计划中的位置：`第 3 周 / 第 2 个重点模块`

**中间主内容区**
按 tab 切换，推荐 4 个 tab：
1. `任务说明`
2. `知识点`
3. `笔记`
4. `关联复习`

**底部固定操作栏**
- `开始/暂停计时`
- `完成任务`
- `遇到问题`
- `问 AI`

### 12.3 按钮功能
#### 1）开始/暂停计时
- 开始后按钮变成暂停
- 页面顶部出现小型计时条
- 退出页面时弹窗：
  - `继续后台计时`
  - `暂停并退出`

#### 2）完成任务
点击后弹出完成确认弹层：
- 本次实际用时
- 主观难度（1~5）
- 掌握度自评（不会 / 模糊 / 会了）
- 是否产生错题
- 是否需要插入复习强化
完成后跳转：
- 如果还有下一个 MUST：弹出 `继续下一个`
- 否则回今日计划页

#### 3）遇到问题
弹出二级菜单：
- `时间不够`
- `内容太难`
- `被打断了`
- `资料缺失`
- `想换任务`
不同选项分别进入：
- 快速延后
- AI 解释
- 重排
- 标记资源问题

#### 4）问 AI
跳转 AI 对话页，并自动带上上下文：
- 当前任务标题
- 当前知识点
- 用户画像偏好
- 最近掌握度  
因为 AI 侧已经明确要结合**结构化画像、会话上下文和长期摘要记忆**，而不是每次从零开始聊天。[4][10][11][12]

### 12.4 页面内的小按钮
- `查看知识点详情`
- `查看真题/典型题`
- `收藏为难点`
- `加入通勤卡片`
- `标记为易混`
其中“加入通勤卡片”应直接服务于 V0.3 的通勤 5 分钟卡片能力。[6]

### 12.5 关键状态
- **未开始**
- **进行中**
- **中断**
- **完成待确认**
- **完成已生成复习任务**
任务完成后，系统可自动生成 review task，这就是学习闭环的关键一环。[29]

## 13. 突发重排页 / 重排弹层

### 13.1 这是什么界面
这是产品差异化最强的页面之一。  
它不是“改日历”，而是**学习调度器的人类可读前端**。  
产品最大的卖点之一就是“今天只有 2 小时，也能自动重排”，所以这个页必须设计得很顺手。[9]

### 13.2 触发入口
- 今日计划页点击 `突发重排`
- 任务执行页点击 `被打断了`
- 通知提醒中点击 `今日任务超载`
- Backlog 页点击 `一键重新整理`

### 13.3 页面结构
**第一屏：收集突发信息**
- 今日剩余可用时间输入框
- 突发原因选择：
  - 临时有课
  - 实习/工作
  - 情绪低 / 状态差
  - 任务比预估更久
  - 其他
- 用户偏好策略单选：
  - `尽量保住 MUST`
  - `允许顺延`
  - `今天尽量轻一点`
- 开关：
  - `允许压缩 NICE`
  - `允许调整本周顺序`
  - `允许延长总周期`

这些偏好本质上就是调度策略偏好，应该和结构化画像打通，而不是临时文本备注。[10][13][15]

**第二屏：系统给出重排方案**
- `方案 A：保住 MUST`
- `方案 B：平滑顺延`
- `方案 C：降低今日压力`
每个方案展示：
- 今日变更
- 本周影响
- 哪些任务进 backlog
- 是否影响总目标时间

**第三屏：确认应用**
- 主按钮：`应用这个方案`
- 次按钮：`再看看别的方案`
- 文本按钮：`手动微调`

### 13.4 重点按钮
- `查看变化详情`
- `对比旧版本`
- `仅重排今天`
- `重排今天 + 本周`
- `取消并返回旧计划`

### 13.5 必须做的前端细节
这个页面一定要显示：
- `旧计划版本号`
- `新计划版本号`
- `本次重排时间`
- `触发原因`
因为计划和 schedule 本身就是版本化的，前端必须让用户感知“系统不是乱改，而是在生成新版本”。[3]

### 13.6 跳转
- 应用成功 → 返回今日计划页，并高亮变化项
- 选择 `手动微调` → 进入 Backlog 与任务顺序调整页

## 14. Backlog 页面

### 14.1 这是什么界面
这是“计划没做完但不丢失”的缓冲池。  
在产品逻辑里，Backlog 像就绪队列，所有任务都应该可追踪、可恢复、可再排，而不是一旦移出今日计划就消失。[6]

### 14.2 页面结构
顶部 tab：
- `待安排`
- `逾期`
- `可选`
- `已受阻`

每个任务卡展示：
- 任务标题
- 来源：今日溢出 / 重排 / 手动加入 / 复习未完成
- 原计划日期
- 推荐重新安排日期
- 预计时长
- 优先级标签
- 科目标签

底部固定按钮：
- `一键重新安排`
- `批量移动到本周`
- `清理低优先级`

### 14.3 任务卡操作
- 左滑：安排到今天 / 明天 / 本周
- 右滑：删除 / 降低优先级 / 标记不再需要
- 点击进入任务详情页
- 长按进入多选批量模式

### 14.4 跳转
- Backlog → 任务执行页
- Backlog → 重排页
- Backlog → 周计划页

## 15. 晚间复盘页

### 15.1 这是什么界面
这是“日终控制回路”页面。  
系统不是生成一次计划就结束，而是通过**完成率、用时偏差、主观难度、错题情况**不断修正后续排程和掌握度。[18]

### 15.2 页面结构
**顶部标题**
- `晚间复盘`
- 副标题：`用 2 分钟，让明天的计划更像为你而排`

**复盘问卷卡**
1. 今天完成了多少
2. 实际花了多久
3. 哪个任务最卡
4. 今天状态如何
5. 是否新增错题
6. 是否有临时变化需要同步到时间模板

**自动总结卡**
- `今天你完成了 4/7`
- `OS 比预估多花 35 分钟`
- `建议明天减少 1 个 NICE 任务`
这一段很适合由系统自动生成，但展示必须简洁，不要一大段 AI 长文。[21]

**底部按钮**
- `生成明日建议`
- `上传错题`
- `稍后再复盘`

### 15.3 必填项与选填项
**必填**
- 今日完成率
- 用时偏差
- 主观难度

**选填**
- 心情
- 备注
- 错题上传
- 时间模板变更建议

### 15.4 完成后的结果
完成复盘后，系统可触发：
- 更新掌握度
- 生成 review task
- 更新估时模型
- 触发次日计划微调  
这正对应反馈闭环的设计目标。[18][29]

## 16. 复习任务页

### 16.1 这是什么界面

- `今天到期`
- `已逾期`
- `未来 7 天`
- `全部`

底部浮动按钮：

然后系统根据结果更新：
- 下次间隔
- 掌握度
- 是否插入强化任务

## 17. 错题列表页

### 17.1 这是什么界面
这是用户所有错题的总入口，承担“查找、回看、标签过滤、再次复习”的功能。  
错题链路当前是最小闭环，前端要先做稳定的元数据管理，不要一上来堆过多花哨智能能力。[11][29]

### 17.2 页面结构

- 支持搜索：题干关键词 / 标签 / 知识点

筛选条：
- 科目
- 章节
- 标签
- 来源类型：拍照 / 手动录入 / OCR 导入
- 状态：未整理 / 已整理 / 待复习 / 已掌握

列表卡片：
- 缩略图
- 错题标题（自动摘要）
- 科目 / 章节
- 错因标签
- 最近复习时间
- 当前状态

底部浮动按钮：
- `+ 录入错题`

### 17.3 卡片操作
- 点击：进入错题详情
- 左滑：加入今日复习 / 删除
- 右滑：重新 OCR / 编辑标签

## 18. 错题上传页

### 18.1 这是什么界面
这是拍照录题入口。  
当前对象存储和 OCR 还是偏骨架状态，所以前端一定要把这个页设计成**异步提交 + 可失败重试 + 可稍后完善**，不能假设“用户一上传就秒出完美结构化结果”。[11][29]

### 18.2 入口
- 错题列表页 `+ 录入错题`
- 晚间复盘页 `上传错题`
- 任务完成弹层 `这题我做错了`

### 18.3 页面结构
第一步：选择来源（底部弹层）
- `拍照`
- `从相册选择`
- `从文件导入`

第二步：图片预览
- 裁剪
- 旋转
- 多张合并
- 删除当前张
- 添加下一张

第三步：上传确认
- 科目（可选）
- 章节（可选）
- 备注（可选）
- 主按钮：`开始识别`

### 18.4 关键按钮
- `重拍`
- `继续添加`
- `开始识别`
- `先存原图，稍后识别`

最后这个“先存原图，稍后识别”很重要，因为 OCR 建议走异步 job，不要阻塞主链路。[29][21]

## 19. OCR 处理中页 / 结果确认页

### 19.1 处理中页
页面内容：
- 大图标 + 动效：`正在识别`
- 进度提示：
  - `图片上传完成`
  - `OCR 识别中`
  - `结构化解析中`
  - `等待你确认`
- 按钮：
  - `回到错题列表`
  - `后台继续处理`

### 19.2 结果确认页
用户看到的是一份“待确认结构化结果”：
- 题目标题
- 科目
- 章节
- 题干文本
- 用户答案
- 正确答案
- 错因标签
- 难度
- 是否加入复习

# 五、全局跳转关系与状态机

产品状态建议和页面要一一对应，避免前端导航混乱。  
整个流程最适合映射成：  
`未登录 → 已登录 → Onboarding → 全局计划就绪 → 本周激活 → 今日 check-in → 今日执行 → 晚间复盘 → 周复盘`。[18]

### 30.1 主跳转链路
1. 启动页 → 登录页  
2. 登录页 → Onboarding  
3. Onboarding → 目标创建成功  
4. 目标创建成功 → 全局计划生成页  
5. 全局计划确认 → 今日计划页  
6. 今日计划页 → 任务执行页  
7. 任务执行页 → 晚间复盘页 / 重排页 / AI 对话页  
8. 晚间复盘页 → 复习任务页 / 错题上传页  
9. 周结束 → 周报页  
这个顺序正好对应当前产品最小闭环路线图。[6][18]

### 30.2 关键二级跳转
- 今日计划 → Backlog
- 今日计划 → 知识点详情
- 任务执行 → 错题上传
- 错题详情 → AI 讲解
- AI 讲解 → 生成通勤卡片
- 周报 → 一键调整下周计划

# 六、补充的异步态、空态、错误态规范

---

## 31. AI 与 OCR 一律做“异步友好前端”
因为 AI 与 OCR 都不适合假设“秒回、永不失败”，前端需要统一的 job 状态组件，至少支持：
- 排队中
- 处理中
- 成功
- 失败
- 可重试  
这既符合 AI 请求分级的架构，也符合 OCR 挂异步任务的设计原则。[21][29]

## 32. 必须统一的空态
- 没有今日计划
- 没有 backlog
- 没有复习任务
- 没有错题
- 没有 AI 历史
- 没有周报数据

## 33. 必须统一的错误态
- 网络失败
- OCR 失败
- AI 生成超时
- 上传失败
- 计划生成失败
每个错误态都要有明确按钮：
- `重试`
- `稍后再试`
- `切换到手动模式`
